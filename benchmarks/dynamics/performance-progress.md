# GlySys performance milestone progress

Last updated: 2026-09-26. Results below distinguish diagnostic throughput from
numerical and trajectory qualification. The user accepted an approximate
220 ns/day explicit-GPU core-throughput target; the earlier 80%-of-OpenMM
throughput target is superseded for this milestone. Scientific equivalence gates
are unchanged and remain mandatory.

Current scoped target: native explicit 1CRN NVT at 2 fs around 220 ns/day core
throughput, with scientific equivalence to OpenMM and browser/WebGPU and ReGlyco
integration. The full CPU/implicit 0.80x OpenMM throughput matrix is no longer a
release target for this milestone. Preserve historical and untracked work.

The explicit GPU 0.3 ns trajectory gate now passes across two independent replicas
after correcting the LF-middle solute constraint impulse. The implicit GPU gate
remains inconclusive after the predeclared maximum of three independent replicas:
10 ps blocks retain correlation and the energy confidence-width criterion is not

## Implemented

- Backwards-compatible `langevinDiscretization` protocol field (`baoab` default, `lf-middle` opt-in), serialized `h-bonds` constraints, checkpoint velocity convention, and distinct LF-middle model versions.
- CPU LF-middle sequence and implicit X-H constraints, plus explicit/implicit GPU LF-middle entry points with 2 fs constrained smoke coverage.
- Run scheduling uses completed endpoints, splits at frame/checkpoint/stage/observation boundaries, preserves the step-zero checkpoint, throttles progress, and avoids flushing empty trajectory batches.
- Scalar-only `--observables-every` output; benchmark warmup, fixed-step/duration windows, repeat, JSON, and starting-checkpoint options. Duration sampling adapts batch length; `--ending-checkpoint` is available for reproducible diagnostics.
- CPU implicit force-only steps avoid ordinary per-step energy evaluation; OBC2 pair work no longer materializes a full pair list or worker-sized full-system gradient buffers; torsions use fixed-size analytic geometry derivatives.
- GPU implicit OBC2 lane variants and resident LF-middle execution; existing GPU force and restart tests remain available.
- LF-middle solute position projection now uses previous-step bond directions in the CPU reference and both GPU shaders; legacy BAOAB retains its prior path. The change followed a deterministic force-free three-X-H fixture averaging 216.57 K with the former trial-direction SHAKE, while its velocity-projection-only control sampled the target. The updated constrained CPU temperature regression and targeted implicit CPU/Vulkan 2 fs parity test pass.
- Corrected the explicit GPU LF-middle dispatch to run both nonbonded and bonded force passes at the new coordinates. A regression test compares resident post-step energy/gradients to a fresh evaluation. Before this fix, a full-system force refresh was stale and caused CPU/GPU coordinates to diverge catastrophically within 2–8 steps.
- Explicit GPU solute RATTLE uses a scale-aware relative convergence check to avoid exhausting its 200 sweeps at f32 residual floors; diagnostics retain the absolute residual.
- Optional explicit-GPU neighbor skin selection is exposed in the native CLI and diagnostics; it changes rebuild frequency, not the physical cutoff. A short 2 fs sweep did not show a better setting than the 1.5 Å default.
- GPU compute-pass timestamp queries are now available when requested and supported by the adapter. Unsupported devices report unavailable rather than fabricating stage times.
- The optional native explicit tiled path now uses fixed 640-entry neighbor rows, a single neighbor traversal per rebuild, deterministic GPU sorting, and cooperative 64-lane force evaluation. It remains opt-in; the default browser/runtime CSR path is unchanged. Capacity overflow is reported rather than truncating neighbors.
- The 1CRN benchmark orchestrator now accepts `--explicit-gpu-tiled-nonbonded` and records the selected explicit kernel layout in its manifest.
- Added the target-specific `getrandom/wasm_js` feature so the wasm runtime builds without changing native RNG behavior.
